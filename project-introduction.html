Project Overview

不是传感器堆料，而是一个完整嵌入式闭环

项目把环境安全监测拆成采集、通信、显示、报警、交互和记录几个边界清晰的模块。两块板分工明确，同一套源码通过 APP_NODE_ROLE 编译出两个固件，兼顾演示效果和工程可维护性。

A

采集节点专注输入

SENSOR 周期读取 DHT11、MQ135、MQ2、雨量、热敏和火焰模块，将数据滤波后封装成协议 v2 固定帧发送。

B

监控节点专注输出

MONITOR 流式解析串口帧，刷新 OLED，驱动蜂鸣器，并处理 K1/K2 页面、静音和阈值档位操作。

C

异常状态可观察

通信超时会进入 NODE LOST，传感器异常和危险条件会映射到 OLED 状态、JSON 风险和蜂鸣节奏。

Architecture

双节点架构与运行链路

这里展示的是系统逻辑架构，不包含错误接线图。答辩时可以沿着这条链路讲清楚数据如何从采样到报警。

职责划分

USART1 保留给 CH340C 调试口，USART3 负责板间通信。接收端使用中断环形缓冲，主循环做帧解析和状态判断， 这样 OLED 刷新、按键扫描和报警更新互不抢占关键串口接收路径。

软件采用 super-loop 时间片调度：采集、解析、显示、报警、记录都有独立周期，不引入 RTOS 也能保持结构清楚。

采样

读取温湿度、空气质量、烟雾和火焰状态。

预处理

ADC 值做指数滑动平均，DHT11 错误写入状态位。

编码

使用 22 字节协议 v2 固定帧承载雨量、热敏、状态位、序号和 checksum。

解析

MONITOR 使用流式解码器寻找帧头，校验长度、版本和累加和。

输出

OLED、蜂鸣器、JSON Lines 和可选 Flash 记录同步更新。

Alarm Strategy

报警状态优先级

系统把输出状态做成清楚的四档，方便现场演示，也方便调试时快速定位问题。

正常

通信在线且无警告、无危险。OLED 显示 NORMAL，蜂鸣器关闭。

预警

空气质量、烟雾、雨量、热敏或 DHT11 状态触发预警条件，蜂鸣器保持关闭。

危险

检测到火焰、MQ2 严重超标或热敏高温，蜂鸣器快速鸣响。

节点丢失

超过超时时间没有有效采集帧。OLED 显示 NODE LOST，蜂鸣器慢速提示。

Demo Workflow

答辩演示流程

建议按“固件、通信、显示、报警、恢复”顺序演示，逻辑最稳，也最容易讲出工程价值。

烧录两个固件

SensorDebug 输出烧录到板 A，MonitorDebug 输出烧录到板 B。

确认串口日志

两个 CH340C 调试口均使用 115200 8N1，分别观察 SENSOR 和 MONITOR 日志。

观察 OLED 与看板

确认 OLED 显示传感器值，Web Serial 看板显示 JSON schema v2 数据，K1 切换页面，K2 短按静音、长按切换阈值档位。

触发风险状态

用安全、可控的方式改变 MQ、雨量、热敏或火焰模块输入，观察 OLED、看板风险和蜂鸣器节奏。

验证异常恢复

断开板间通信后应进入 NODE LOST，恢复通信后回到实时接收。
